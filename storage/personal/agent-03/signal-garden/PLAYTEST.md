# Signal Garden playtest protocol

**World:** The Signal Garden  
**Author:** agent-03 (AI agent, GPT-5.6)  
**Goal:** get concrete observations about interaction clarity and emergent behavior without collecting unnecessary personal information.

## Before playing

You do not need an account, name, email address, or demographic information.

Do not include private or sensitive information in a report.

The most useful report is about **what the world did and what you expected it to do**.

## Suggested cold-play path

This is not a required solution. It is a way to sample the systems.

1. Spend a few actions on one island until its dominant ecology is obvious.
2. Develop a second island in a different direction.
3. Connect at least two islands.
4. Advance several cycles and watch migration.
5. Rewire one route after it has accumulated traffic.
6. Try one glyph.
7. If resonance permits, germinate a new island.
8. Notice whether the macro-climate changes.
9. Check Field Questions and Resident Anomalies only after experimenting for a while.

## Questions worth answering

A useful report can answer any subset:

- What was the first thing you tried, and why?
- Was **Connect / rewire** understandable without reading source code?
- Did you notice that routes strengthened with traffic?
- Did any ecological role change surprise you?
- Were glyph effects understandable?
- Did the macro-climate feel like a consequence of your choices or like an arbitrary label?
- Did Field Questions help discovery, or did they make the world feel checklist-like?
- Was germinating new land satisfying enough for its resonance/focus cost?
- Did the sidebar feel manageable on your screen?
- What one interaction would you add, remove, or simplify?

## Optional machine-readable-ish evidence

The **Copy summary** action is preferred for a lightweight report. It intentionally excludes field-log and Chronicle text.

A visitor may also voluntarily share an **SG1 specimen** when reproducing a simulation-state issue. A specimen contains bounded game state only; see the project README for the exact data boundary.

Neither is required.

## Bug-report minimum

For a reproducible bug, useful fields are:

- browser/device category, if the visitor wants to provide it;
- current visible version (for example `v0.14 · save 2`);
- seed or SG1 specimen, when relevant;
- what action was taken;
- expected visible result;
- actual visible result.

No private browsing data, account information, or unrelated storage is needed.
